# Connector Documentation

## 1. Outputs

Outputs must be stored in the following paths:

* **Raw outputs:** `/outputs/raw`
* **Final outputs (common schema):** `/outputs/common`

### JSON filenames in `/outputs/common`

Files must follow this format:

```text
{AIRFLOW_DAG_ID}_{RUN_ID}_{random_id}.json
```

### Output filenames in `/outputs/raw`

There is flexibility regarding the filename, but it is recommended to include at least the following fields to make identification easier:

```text
{connector_id}_{airflow_dag_id}_{run_id}_{source_name}
```

---

## 2. Input URLs

The script's input URLs must always be provided after the `-i` parameter.

### Example

```bash
scrapper.py -i http://link1 http://link2
```

The connector's main script, which will be executed from the `Dockerfile`, must always support this parameter.

Even if the connector uses a single fixed URL, it must still be executed in this way:

```bash
scrapper.py -i http://link
```

---

## 3. `ENTRYPOINT` in the Dockerfile

The image must execute the connector's main script **without any parameters** and must be built using `ENTRYPOINT`, so that parameters can be passed when creating the container.

### Example

```dockerfile
ENTRYPOINT ["python", "main.py"]
```

---

## 4. Common Schema

**One JSON file must be generated for each collected news article** with the following fields:

```json
{
  "id": "random news article id",
  "source_url": "https://24horas.com",
  "canonical_url": "https://24horas.com/news/123",

  "airflow_dag_id": "Airflow DAG ID that launched the connector",
  "extracted_at": "datetime when the script started running",
  "published_at": "datetime when the news article was published",
  "airflow_run_id": "execution identifier",

  "connector_id": "ID of the connector used to extract the news article",
  "connector_name": "connector name",

  "source_name": "24 Horas",
  "source_type": "tv",
  "language": "es",
  "country": "ES",
  "source_tags": ["news", "television", "spain"],

  "title": "news article title",
  "content": "news article text"
}
```

### Optional fields

* `canonical_url`: include only if `source_url` is not sufficient.
* `published_at`: include only if available.
* `title`: include only if available.

### Information obtained from the seed list

The following fields come from the seed list:

* `source_name`
* `source_type`
* `language`
* `country`
* `source_tags`

---

## 5. Using Environment Variables to Complete the Common Schema

Connector scripts must obtain external variables from Airflow and the seed list through environment variables.

These variables are divided into two types:

---

### a) Global Variables

These are shared by all JSON files generated by the connector.

They are assigned directly as key-value pairs:

| JSON Field       | Environment Variable |
| ---------------- | -------------------- |
| `airflow_dag_id` | `AIRFLOW_DAG_ID`     |
| `airflow_run_id` | `AIRFLOW_RUN_ID`     |
| `extracted_at`   | `EXTRACTED_AT`       |
| `connector_id`   | `CONNECTOR_ID`       |
| `connector_name` | `CONNECTOR_NAME`     |

---

### b) Source-Dependent Variables

When the connector receives multiple input sources, each JSON file must include the data corresponding to its specific source.

These variables are provided as string lists separated by `::`.

### Example

```bash
SOURCE_NAME="24 HORAS::OndaCero::Radio RNE"
```

When implementing the connector, it is assumed that the order of the values matches the order of the sources passed as parameters to the script.

For each source `i`, the JSON fields are assigned as follows:

| JSON Field    | Variable         |
| ------------- | ---------------- |
| `source_name` | `SOURCE_NAME[i]` |
| `source_type` | `SOURCE_TYPE[i]` |
| `language`    | `LANGUAGE[i]`    |
| `country`     | `COUNTRY[i]`     |
| `source_tags` | `SOURCE_TAGS[i]` |

---

# Documentación de conectores

## 1. Outputs

Los outputs deben almacenarse en las siguientes rutas:

- **Outputs raw:** `/outputs/raw`
- **Outputs finales (esquema común):** `/outputs/common`

### Nombre de los JSON en `/outputs/common`

Los archivos deben seguir este formato:

```text
{AIRFLOW_DAG_ID}_{RUN_ID}_{random_id}.json
````

### Nombre de los outputs en `/outputs/raw`

Se deja libertad en el nombre, pero se recomienda incluir al menos los siguientes campos para facilitar su identificación:

```text
{connector_id}_{airflow_dag_id}_{run_id}_{source_name}
```

---

## 2. Enlaces de entrada

Los enlaces de entrada del script deben ir siempre después del parámetro `-i`.

### Ejemplo

```bash
scrapper.py -i http://enlace1 http://enlace2
```

Es obligatorio que el script principal del conector que se ejecutará desde el `Dockerfile` funcione siempre con este parámetro.

Aunque el conector utilice un único enlace fijo, igualmente debe ejecutarse de esta forma:

```bash
scrapper.py -i http://enlace
```

---

## 3. `ENTRYPOINT` en el Dockerfile

La imagen debe ejecutar el script principal del conector **sin ningún parámetro** y debe construirse usando `ENTRYPOINT`, de forma que permita pasar parámetros al crear el contenedor.

### Ejemplo

```dockerfile
ENTRYPOINT ["python", "main.py"]
```

---

## 4. Esquema común

Debe generarse **un JSON por cada noticia recopilada** con los siguientes campos:

```json
{
  "id": "id aleatorio de la noticia",
  "source_url": "https://24horas.com",
  "canonical_url": "https://24horas.com/noticia/123",

  "airflow_dag_id": "dag id de airflow que lanzó el conector",
  "extracted_at": "datetime de cuando se empezó a ejecutar el script",
  "published_at": "datetime de cuando se publicó la noticia",
  "airflow_run_id": "identificador de la ejecución",

  "connector_id": "id del conector usado para extraer la noticia",
  "connector_name": "nombre del conector",

  "source_name": "24 Horas",
  "source_type": "tv",
  "language": "es",
  "country": "ES",
  "source_tags": ["informativos", "television", "espana"],

  "title": "título de la noticia",
  "content": "texto de la noticia"
}
```

### Campos opcionales

* `canonical_url`: incluir solo si `source_url` no es suficiente.
* `published_at`: incluir solo si está disponible.
* `title`: incluir solo si está disponible.

### Información obtenida de la seed list

Los siguientes campos provienen de la seed list:

* `source_name`
* `source_type`
* `language`
* `country`
* `source_tags`

---

## 5. Uso de variables de entorno para completar el esquema común

Los scripts del conector deben obtener las variables externas de Airflow y de la seed list mediante variables de entorno.

Estas variables se dividen en dos tipos:

---

### a) Variables globales

Son comunes para todos los JSON generados por el conector.

Se asignan directamente como pares clave-valor:

| Campo JSON       | Variable de entorno |
| ---------------- | ------------------- |
| `airflow_dag_id` | `AIRFLOW_DAG_ID`    |
| `airflow_run_id` | `AIRFLOW_RUN_ID`    |
| `extracted_at`   | `EXTRACTED_AT`      |
| `connector_id`   | `CONNECTOR_ID`      |
| `connector_name` | `CONNECTOR_NAME`    |

---

### b) Variables dependientes de la fuente

Cuando el conector recibe múltiples fuentes de entrada, cada JSON debe incluir los datos correspondientes a su fuente específica.

Estas variables se proporcionan como listas en formato string separadas por `::`.

### Ejemplo

```bash
SOURCE_NAME="24 HORAS::OndaCero::Radio RNE"
```

Al programar el conector, se asume que el orden de los valores coincide con el orden de las fuentes pasadas como parámetro al script.

Para cada fuente `i`, los campos del JSON se asignan de la siguiente forma:

| Campo JSON    | Variable         |
| ------------- | ---------------- |
| `source_name` | `SOURCE_NAME[i]` |
| `source_type` | `SOURCE_TYPE[i]` |
| `language`    | `LANGUAGE[i]`    |
| `country`     | `COUNTRY[i]`     |
| `source_tags` | `SOURCE_TAGS[i]` |
